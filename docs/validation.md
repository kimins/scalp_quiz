### 3일 DB와 충돌

`python -m scalp_db build --cache cache --out data/lookup --windows 3`로 생성했습니다. 현재 manifest는 3일 DB만 참조합니다.

2,240,133개 정렬 레코드의 키를 모두 검사했고 모호한 조회 키가 없었습니다. 현 수집본에는 5일 fallback이 필요하지 않습니다. 이후 캐시를 갱신하면 충돌 통계를 다시 계산해야 합니다. 추정 크기에는 확장 UI·기타 자산은 포함하지 않습니다.

실제 레코드의 `stockId` 범위는 0~2,755, 마지막 날짜는 2023-01-02~2026-09-22, 다음 날짜는 2023-01-03~2026-09-23입니다. 모두 uint16 범위에 들어갑니다. `python -m scalp_db verify --out data/lookup --cache cache`는 2,240,133개를 원본 캐시에서 재계산해 전수 대조했고 `sourceVerified=true`로 끝났습니다.

### 실제 quiz HAR 회귀

Python 전체 테스트 13개 통과(위 실제 HAR 회귀 1개 포함). `node scripts/check_browser.mjs data/lookup cache <code>`를 여섯 코드에 각각 실행해 총 5,152개 JS 조회 레코드의 다음 날짜와 독립 정수 수익률 계산이 일치했습니다. 브라우저 조회기는 다중 후보를 배열로 보존하며, 2개 후보를 담은 합성 바이너리도 실제 `LookupDB.lookup()`으로 확인했습니다. Python 합성 충돌·캐시 손상·수집 실패 빌드 차단 테스트도 통과했습니다.

`scripts/check_har_regression.mjs`의 Node.js 로컬 파일 fetch 모사 측정(2회): 전체 DB 로드·해시 확인 약 98~127ms, 로드 후 각 600회 fingerprint 조회 평균 0.031~0.035ms, p95 0.047~0.053ms, 최악 0.503~0.617ms. 이 수치는 Chrome에서의 실제 네트워크·서비스 워커 시작 시간을 뜻하지 않습니다.

MV3 확장에서는 `web/lookup.mjs`와 manifest가 참조하는 DB 파일을 패키지에 넣고, 확장 페이지 또는 `type: "module"` 서비스 워커에서 `chrome.runtime.getURL('db/')`로 로드할 수 있습니다. [Chrome의 ES module 서비스 워커 문서](https://developer.chrome.com/docs/extensions/get-started/tutorial/service-worker-events)와 [확장 내부 fetch 문서](https://developer.chrome.com/docs/extensions/develop/security-privacy/stay-secure)를 기준으로 정적 import와 내부 파일 fetch 사용 가능성을 확인했습니다. Node에서 로드·조회는 확인했지만 이 저장소에는 확장 UI/manifest가 없어 실제 Chrome 설치 검증은 수행하지 않았습니다. 현재 시장 목록은 과거 상장폐지 종목을 모두 포함하지 않으며, Naver 제공 가격이 향후 재조정되거나 퀴즈 제공자와 달라지면 해당 HAR 회귀가 실패하도록 했습니다.
